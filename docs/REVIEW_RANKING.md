# ファイトフライト順位連携・公開前独立レビュー

2026-09-29、Sol Highがゲーム、実験場、DB移行案を実装担当とは別に確認した。対象は任意の名前とゲスト開始、モード別順位、結果画面、低高度終了、宙返り中止、旋回補助、効果音、公開ゲート。ゲーム基点は `main` の `6b6de91`。これはコードレビューとローカル検査の記録であり、iPhone実機での試遊や公開後の検証ではない。

## 解消した指摘

- DB移行の `pg_catalog.coalesce` は無効な指定だった。通常の `coalesce` に修正後、本番移行とロールバック付きの匿名・記名開始、終了、再送、集計検査が通った。両ゲーム行は `is_active=false`、検査用プレイと得点は残っていない。記名の既存RPCと新規ゲストRPC、公開権限、各列の契約を照合した。
- 実験場の固定一覧が接続失敗時に未公開ゲームを表示する経路を指摘した。固定一覧・詳細の新規項目を非公開とし、DBの有効な行からだけ表示するよう修正した。名前未登録の回数はモード別の専用集計RPCから読み、順位の外に明示する。
- 開始RPCの応答待ち中に結果が確定すると、古いキュー内容で確定スコアを上書きする競合を指摘した。応答後に最新の保存内容を取り込み、遅延開始と終了の順序をテストした。ゲスト終了を保存すると再読込時に全キューを不正扱いする不整合も、ゲストには結果を保存しない形で解消した。公開前の `game_not_available` も再試行可能に分類した。
- 宙返り中止時に姿勢が一周分戻り続ける経路と、操縦を保持したまま宙返りを開始できない経路を指摘した。現在姿勢を同じ向きの正規角へ変換し、新しい操縦操作だけで中止する修正を確認した。10〜95%の中止、同方向の新操作、保持中の開始、完了時のみ加点をテストしている。
- マニフェストの「出撃前の名前必須」は任意名の仕様と矛盾していた。実験場のスキーマを本作に限って拡張し、`required_before_start=false`、`required_for_ranking=true`、匿名開始RPCを宣言した。他作品の名前必須契約は維持する。Draft 2020-12検証で本作と既存例が通り、不整合な6例は拒否された（検証実行は主担当）。

## 独立検査と限界

私自身の最終コード検査で `npm test` は50/50成功、`npm run build` も成功した。ビルドには既存と同種の500kB超チャンク警告が残る。ローカルのテストは匿名開始が得点を送らないこと、記名開始→終了→同一ID送信、遅延応答中の結果凍結、再読込後の再送、30位取得、応答本文のタイムアウトを含む。低高度は両モードで1,200m以下からゲーム時間10秒のラッチと停止中の凍結を確認した。画面操作の模擬端末検査は別担当が実施中であり、このレビュー時点で独立したブラウザ合格とは記録しない。

公開前にはゲームと実験場の配置内容、模擬端末の最終証拠、対象headのChecksを照合し、その後に両DB行を有効化する。現在の匿名開始は本人認証ではなく、任意の別UUIDによる水増しは防げない。意図的なゲスト開始後の同一UUIDを使った記名開始も共通RPC側で二重計上され得る。複数タブが同じ保存キューを更新すると、他タブで完了済みの項目が古いメモリから再出現する場合があるが、同じ開始・提出UUIDでの再送なのでサーバーの回数・得点は増えない。これらは公開前の機能不備ではなく、集計値と端末内の未送信表示を解釈する際の限界である。
